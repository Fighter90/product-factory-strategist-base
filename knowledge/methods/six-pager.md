# Six-pager

## Когда применять
Когда рекомендацию защищают перед комитетом/руководством: нужен компактный (≈6 смысловых страниц)
документ в фиксированной структуре, где каждый раздел отвечает на известный вопрос, а цифры считаются
в Excel-приложениях, а не «в воздухе». В агенте собирается цепочкой `pfs export --six-pager` →
субагент `six-pager-writer` → `pfs check --six-pager` до 0 ошибок.

## Суть
Инструмент не вставляет документы 02/03/04/06 в six-pager — работа разделена:

| Шаг | Что происходит | Что получается |
|---|---|---|
| 1. `pfs export --six-pager` | инструмент собирает **пакет данных** и **каркас** | `outputs/six_pager_pack.json` (+ .md): утверждения с силой (kind/grade), ситуация из 02, варианты и выбор из 03, решения, KPI из 06, расчёты calcs.json, источники; `outputs/SIX_PAGER.md` — каркас FAQ-1…6 со слотами `[СЛОТ …]` и вычисляемыми блоками (юнит-экономика, матрица тактик, KPI-таблица, сноски, приложения) |
| 2. субагент `six-pager-writer` (deep) | пишет текст по слотам по эталону `SIX_PAGER_PROMPT.md`, **только из пакета** | комитет-документ: числа с тегами [C###]/[S###], «Вывод (умозаключение)» в каждом блоке, ≤ 3500 слов основного текста |
| 3. `pfs check --six-pager` | обязательный цикл до 0 ошибок | ворота: слоты закрыты, структура эталона (1.1–2.2, 3.1–3.3), вклад 100%, матрица, KPI двух плоскостей, нет служебных ID и вставок документов |

Шесть FAQ-разделов, каждый — ответ на вопрос принимающего решение:

| Раздел | Вопрос читателя | Откуда берётся (пакет данных, а не вставка файлов) |
|---|---|---|
| FAQ-1 | Что происходит на рынке, кто конкуренты, в чём вызов? | pack → situation + claims: объём и динамика диапазонами, 5–7 трендов с «что это значит для продукта», таблица конкурентов с рисками; «чего не хватает никому» = окно стратегии |
| FAQ-2 | Кто пользователи, какие у них боли по этапам пути? | pack → situation + claims: сегменты по барьеру входа, барьеры по этапам пути и «что сдерживает» |
| FAQ-3 | Какие инициативы предлагаем и почему именно они? | pack → options + choice + claims: вводная про выбор направления (с red team) и 3–4 инициативы-драйвера, по одной на подпункт 3.1–3.3+, расчёт эффекта (формула → подстановка → результат) |
| FAQ-4 | Из чего конкретно состоит каждая инициатива? | pack → options + choice: матрица «Инициатива, Фокус, Потребности, Решения (тактики)», 2–4 строки на инициативу |
| FAQ-5 | Как реализуем и как поймём, что получилось? | pack → kpi + decisions: вклад инициатив в % (сумма 100) с обоснованием весов, порядок тактик, тайминг к сезонам, параллельные треки, решение с триггером стопа |
| FAQ-6 | По каким метрикам меряем успех? | pack → kpi + calculations: KPI бизнес и продукт, база → цель к сроку → порог действия, контр-метрики по ударам red team |

Правила структуры: вклад инициатив в результат суммируется в 100%; каждая инициатива имеет сильные
возражения; «оставить как есть» и «закрыть направление» присутствуют как полноценные альтернативы;
таблица конкурентов «преимущество → риск для нас»; тактики привязаны к потребностям, а не к фичам.
Разбор «хорошо/плохо» по каждому FAQ и типовые ошибки — карта `M-six-pager-etalon`.

## Процедура (агент)
1. Дождаться готовности документов 02/03/04/06 — они источник данных пакета, но не структура документа
   (см. skill `six-pager`).
2. Собрать параметры из реестра утверждений в `projects/<slug>/calcs.json` (каждое значение → C###).
3. Фоновым субагентом: `pfs calc all` → `outputs/attachments/*.xlsx` (юнит-экономика, модель роста,
   когорты, размер рынка; лист «Ввод» с редактируемыми параметрами, расчёты на формулах).
4. `pfs export --six-pager` → пакет данных + каркас; запустить субагент `six-pager-writer` —
   текст по слотам из пакета, без вставки 02–07. EN-версия — по `SIX_PAGER_PROMPT_EN.md`.
5. `pfs check --six-pager` до 0 ошибок; `pfs check --strict`; показать руководителю список
   приложений и что в них редактировать.

## Шаблон / чек-лист
См. `knowledge/templates/six_pager.md` и конспект эталона `knowledge/templates/six_pager_reference_outline.md`.
Чек-лист качества:
- [ ] каждый раздел отвечает на «свой» вопрос, а не пересказывает соседний;
- [ ] числа только с [C###]/[S###]; значения в тексте совпадают с Excel;
- [ ] у каждой инициативы — возражения и вклад в результат (сумма = 100%);
- [ ] метрики с формулами, единицами, периодом и целевым значением;
- [ ] план проверки: база сравнения, срок, контрметрики, критерии продолжить/изменить/остановить;
- [ ] `pfs check --six-pager` — 0 ошибок.

## Типичные ошибки
- «Красивый текст без расчётов»: цифры без модели и источника — читатель не может их проверить.
- Тактики без потребностей: список фич вместо «боль → механика → ожидаемый эффект».
- Склейка вместо письма: вставленный текст 02/03/04/06 вместо слотов по эталону — документ не
  отвечает на вопросы комитета в их порядке (это ворота `pfs check --six-pager`, ошибка «дословная строка»).
- Переполненный FAQ-1: история рынка вместо ответа «что это меняет для решения».
- Метрики без базы сравнения и срока — «вырастим лояльность» не проверяемо.
- Excel с «мёртвыми» числами вместо формул: допущение нельзя пощупать.

## Вопросы, которые могут изменить решение
- Какой вклад каждой инициативы в целевую метрику и на чём он основан?
- Что должно случиться, чтобы мы отказались от инициативы (критерий остановки)?
- Какая цифра в модели самая хрупкая и что её подтвердит дешевле всего?
