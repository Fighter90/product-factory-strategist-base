# Эталон six-pager: конспект структуры референса (Goods Marketplace case)

> Конспект СТРУКТУРЫ эталонного документа «Пример стратегии» (кейс Goods Marketplace,
> курс «Стратегии роста бизнеса и продукта», внешнего университета): разделы, порядок, обязательные таблицы
> и признаки «хорошо». Не копия текста референса — схема, по которой six-pager-writer
> пишет документ комитета. Полная спецификация с правилами — `SIX_PAGER_PROMPT.md`;
> разбор «хорошо/плохо» по каждому FAQ — карта `M-six-pager-etalon`.

## Форма документа

- ≈6 смысловых страниц основного текста (без приложений); основной текст ≤ 3500 слов
  (таблицы и сноски не считаются) — дальше комитет не читает.
- Шесть FAQ-разделов с нумерованными подпунктами (1.1, 1.2, 2.1 …); каждый смысловой блок
  закрывается строкой «**Вывод (умозаключение)**: следовательно / это означает …».
- Без скриншотов и картинок: доказательная форма комитета — таблицы, формулы, расчёты,
  сноски на источники. Число без тега происхождения — не число.
- Внизу — нумерованные сноски-источники; в тексте — теги [C###]/[S###].

## Скелет по разделам

| Раздел | Объём | Обязательные элементы |
|---|---|---|
| FAQ-1. Анализ текущего состояния | ~1 стр. | 1.1 обзор рынка: объём и динамика диапазонами, буллет-прогноз по годам, 5–7 трендов буллетами (жирный заголовок + «что это значит для продукта» + следствие-возможность); 1.2 таблица конкурентов (колонки — группы конкурентов; строки — «Ключевые преимущества», «Стратегия роста и промо-механики», «Риски для компании» с оценкой Высокий/Средний/Низкий) + абзац «чего не хватает никому» = окно стратегии; вывод с окном возможностей и сроком |
| FAQ-2. User Persona | ~1 стр. | 2.1 таблица сегментов (колонки — типы пользователей по барьеру входа; строки — «Кто они?», «Что используют сегодня и почему?», «С какими трудностями сталкиваются?», «Общие трудности») + обоснование приоритизации (ёмкость/CAC/конкуренция); 2.2 таблица «Этап пути → Барьер сегодня → Что делает продукт» (привлечение → выбор → оплата → постоплатный опыт) + «что сдерживает от старта или продления» по сегментам; вывод: сегментация по барьеру, лестница тиров обслуживает все барьеры |
| FAQ-3. Стратегические инициативы | ~1 стр. | вводная: из каких вариантов выбрано направление (отсылка к red team) и почему; 3–4 инициативы-драйвера — по одной на нумерованный подпункт (3.1, 3.2, 3.3…), внутри: «драйвер → Ключевые направления (буллеты) → расчёт эффекта (формула → подстановка → результат)»; вывод: инициативы закрывают барьеры FAQ-2 и опираются на активы |
| FAQ-4. Тактики | ~0,5–1 стр. | матрица «Стратегическая инициатива, Фокус, Потребности и ожидания пользователя, Решения (тактики)»: 2–4 строки на инициативу; тактики исполняемые («что именно строится/меняется»), не лозунги |
| FAQ-5. Высокоуровневый план | ~0,5 стр. | вклад инициатив в общий результат в % — сумма 100%, у каждого веса обоснование; порядок тактик (высокий → средний → базовый); тайминг к сезонам рынка; параллельные треки (комьюнити/партнёрства); решение с обязательством, сроком, пересмотром и триггером стопа |
| FAQ-6. Метрики успеха | ~0,5 стр. | KPI в двух плоскостях: бизнес (выручка/MRR, платящие, конверсия в оплату, доля тарифов, LTV/CAC) и продукт (активация, время до первой ценности, число действий до результата, churn, CSAT/NPS); каждый KPI: база → цель к сроку → порог действия; контр-метрики — по одной на удар red team |
| Сноски-источники | ~0,5 стр. | нумерованный список: источник — название — ссылка; каждое число документа прослеживается до сноски |

## Признаки «хорошо» (почему референс работает)

- Документ отвечает на вопросы комитета в их порядке, а не пересказывает рабочие документы:
  каждая секция — самостоятельный ответ «данные → обоснование → расчёт → вывод».
- Каждый тренд ведёт к следствию-возможности для продукта; каждый конкурент — к риску;
  каждый барьер — к механике, которая его снимает; каждая тактика — к потребности.
- Эффекты считаются, а не декларируются: формула → подстановка → результат; вклад
  инициатив сходится в 100% и объясняет, почему веса именно такие.
- Метрики проверяемы: база, срок, порог действия («при каком значении меняем план»).
- Диапазоны вместо ложной точности там, где источники расходятся; в расчётах —
  консервативная граница.

## Признаки «плохо» (что ловит `pfs check --six-pager`)

- Склейка рабочих документов вместо письма по эталону (дословные строки из 02–07).
- Служебные ссылки без расшифровки: имена файлов, Q#, H#, WBS, «веха M», голые D###.
- Тренды без «что это значит для нас»; конкуренты списком без рисков; тактики-лозунги.
- Вклад инициатив «примерно поровну» или не сходится в 100%.
- Метрики без базы, срока и порога действия; выводы, не отделённые от данных.
- Основной текст больше 3500 слов — комитет не дочитывает.
